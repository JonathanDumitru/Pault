  <action>
Update each of the 6 test methods in ScreenshotTests.swift to use the accessibility identifiers added in Task 1. Replace best-guess queries and fragile fallback chains with identifier-based queries. Specific changes:

1. **testShot01_AIAssist** (line ~157): Replace `app.groups["ai-assist-panel"].exists ? app.groups["ai-assist-panel"] : app.scrollViews.firstMatch` with a query using the real identifier. Since accessibilityIdentifier on a VStack maps to `app.groups["ai-assist-panel"]` in XCUI, the existing query string is correct but the logic should wait for it to exist rather than immediately falling back. Change to:
   ```swift
   let aiAssistPanel = app.groups["ai-assist-panel"]
   _ = aiAssistPanel.waitForExistence(timeout: 5)
   ```

2. **testShot02_BlockEditor** (line ~195): Replace `app.scrollViews["block-canvas"]` fallback chain. The identifier is now real, so use:
   ```swift
   let blockCanvas = app.scrollViews["block-canvas"]
   XCTAssertTrue(blockCanvas.waitForExistence(timeout: 5), "Block canvas must be visible")
   ```
   Remove the `Thread.sleep(forTimeInterval: 2.0)` fallback since we now wait on a real element.

3. **testShot04_LibrarySplitView** (line ~252): Replace `app.buttons["sidebar-toggle"]` best-guess with the now-real identifier. The existing query string matches the identifier we added, so just remove the `!sidebarToggle.isSelected` check (isSelected is unreliable for toolbar buttons) and simplify to:
   ```swift
   let sidebarToggle = app.buttons["sidebar-toggle"]
   if sidebarToggle.waitForExistence(timeout: 2) {
       // Sidebar should already be visible in screenshot mode, but ensure toggle is available
   }
   ```

4. **testShot05_MenuBarPopover** (line ~296): Replace `app.statusItems["pault-menu-bar-item"]` fallback. The menu bar status item uses NSStatusItem (AppKit), not SwiftUI accessibilityIdentifier. Keep the existing `app.menuBars.buttons["Pault"]` primary query as-is since that is the correct way to find a menu bar extra in XCUI. Remove the `app.statusItems["pault-menu-bar-item"]` fallback entirely since that API does not exist.

5. **testShot06_AnalyticsDashboard** (line ~320): The analytics navigation currently guesses button labels. Since AnalyticsView is presented as a sheet/navigation destination from the sidebar, the existing `app.buttons["Analytics"]` query should work if the sidebar has an Analytics label. Keep the primary query but add a comment noting the identifier "analytics-view" can be used to verify the view loaded:
   ```swift
   // Verify analytics view loaded
   let analyticsView = app.groups["analytics-view"]
   XCTAssertTrue(analyticsView.waitForExistence(timeout: 5), "Analytics view must be visible")
   ```

6. **Add a file-level comment** replacing the existing NOTE on line 27-29 with:

Remove ALL comments containing "best-guess" or "adjust based on actual accessibility tree" since identifiers are now defined.
