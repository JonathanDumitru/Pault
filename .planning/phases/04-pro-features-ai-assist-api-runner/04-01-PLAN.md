<objective>
Build the Cloudflare Worker proxy service and rewire AIService to route Claude/OpenAI calls through it.

Purpose: The proxy is the foundation for all AI features -- it handles subscription auth, rate limiting, API key forwarding, SSE streaming passthrough, optional caching, and token/cost metadata. Without it, no AI feature can ship.

Output: A deployable Cloudflare Worker in a subdirectory (pault-proxy/), AIService rewired to use proxy for Claude/OpenAI (Ollama stays direct), ProStatusManager providing JWS tokens, and a ProxyConfig type for URL/stream event management.

NOTE: CONTEXT.md says "Proxy lives in a separate repo -- Pault repo stays Swift-only." For pragmatic reasons during development, pault-proxy/ is created as a subdirectory within the Pault repo. It is a self-contained Node/TypeScript project with its own package.json and can be factored into its own repo post-launch. This avoids cross-repo coordination during development while preserving the separation of concerns.
</objective>

  <files>pault-proxy/src/index.ts, pault-proxy/wrangler.jsonc, pault-proxy/package.json, pault-proxy/tsconfig.json</files>
  <action>
Create the pault-proxy/ directory at the repo root (sibling to Pault/, separate from the Xcode project).

**pault-proxy/package.json:** Minimal with `"type": "module"`, devDependencies for `wrangler` and `@cloudflare/workers-types`, scripts for `dev`, `deploy`, `types`.

**pault-proxy/tsconfig.json:** Target ES2022, module ESNext, strict true, types from `@cloudflare/workers-types`.

**pault-proxy/wrangler.jsonc:** Name "pault-proxy", compatibility_date "2024-09-23", main "src/index.ts". KV namespace binding `RESPONSE_CACHE`. Rate limit binding `AI_LIMITER` with `simple: { limit: 30, period: 60 }` (30 requests/min per subscriber).

**pault-proxy/src/index.ts:** Single Worker entry point implementing:

1. **Request validation:** Only POST to `/v1/complete` or `/v1/stream`. Return 405 on other methods, 404 on unknown paths. Extract headers: `X-Provider` (claude|openai), `X-Provider-Key`, `X-Storekit-JWS`, `X-Streaming` (true|false), `X-Cache-Opt-In` (true|false).

2. **StoreKit JWS verification:** Decode the JWS (base64url split on `.`), parse payload JSON, check `productId` includes "pro" and `expiresDate` (milliseconds since epoch) is in the future. For v1, trust decoded payload fields (simpler approach per research -- BYOK means attacker would use their own key). Extract `originalTransactionId` as subscriber ID.

3. **Rate limiting:** Use `env.AI_LIMITER.limit({ key: subscriberID })`. On failure, return 429 with `Retry-After: 60` header and JSON body `{"error":"rate_limit","retry_after":60}`.

4. **Provider routing:** Map provider header to upstream URL:
   - claude: `https://api.anthropic.com/v1/messages`
   - openai: `https://api.openai.com/v1/chat/completions`
   Build upstream headers per provider (claude: `x-api-key` + `anthropic-version: 2023-06-01`; openai: `Authorization: Bearer`). Forward request body as-is.

5. **Non-streaming path (`/v1/complete`):** Fetch upstream, read full response, extract token counts from response JSON (claude: `usage.input_tokens`/`usage.output_tokens`; openai: `usage.prompt_tokens`/`usage.completion_tokens`). Calculate estimated cost using hardcoded per-1K-token rates (claude-sonnet: $3/$15 per 1M input/output; gpt-4o: $2.50/$10 per 1M). Return upstream response body with added `X-Input-Tokens`, `X-Output-Tokens`, `X-Estimated-Cost-USD` response headers. If `X-Cache-Opt-In: true`, store in KV with SHA-256 content hash key and 24h TTL.

6. **Streaming path (`/v1/stream`):** Use `TransformStream` to intercept the upstream SSE stream. Pipe upstream `body` through a transform that:
   - Passes each SSE `data:` line through unchanged
   - Accumulates token text for counting
   - Before the final `[DONE]` event, injects a `data: {"metadata":{"input_tokens":N,"output_tokens":N,"estimated_cost_usd":X}}` event
   - Then passes through `data: [DONE]`
   Set response headers: `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive`.

7. **Content safety:** Reject requests where body size exceeds 500KB (roughly 100K tokens). Basic keyword check on request body is discretionary (can be a simple blocklist array, checked case-insensitively).

8. **Error handling:** Upstream errors (non-2xx) forwarded to client as-is with original status code. Wrap all handler logic in try/catch, return 500 with `{"error":"internal"}` on unexpected errors.

Do NOT run `npm install` or `wrangler deploy` -- the proxy is a deliverable for the user to deploy from their own Cloudflare account.

- Add `private(set) var currentTransactionJWS: String?` property.
- In `refreshStatus()`, after iterating `Transaction.currentEntitlements`, capture the JWS: `for await result in Transaction.currentEntitlements { if case .verified(let tx) = result { currentTransactionJWS = result.jwsRepresentation; ... } }`. Store the most recent verified transaction's `jwsRepresentation`.
- Add `func refreshJWSIfNeeded() async` that re-fetches if `currentTransactionJWS` is nil or last refresh was >60 seconds ago (use a `private var lastJWSRefresh: Date?` property). This prevents stale JWS per Pitfall 3 in research.

**Modify Pault/Services/AIService.swift:**
- Add `subscriptionRequired` case to `AIError` enum: `case subscriptionRequired` with description "Pro subscription required for AI features."
- Add `rateLimited(retryAfter: Int)` case to `AIError` with description "Rate limit reached. Try again in {retryAfter}s."

- **Rewire `buildRequest`:** For `.claude` and `.openai` providers, replace direct API URL construction with proxy URL. Build request as:
  ```
  URL: ProxyConfig.baseURL + "/v1/complete"
  Method: POST
  Headers: Content-Type: application/json, X-Provider: {provider.rawValue}, X-Provider-Key: {apiKey}, X-Storekit-JWS: {jws}
  Body: Same provider-specific body as before (model, messages, system, max_tokens)
  ```
  For `.ollama`, keep the existing direct URL path unchanged (localhost:11434).
  Call `await ProStatusManager.shared.refreshJWSIfNeeded()` before building non-Ollama requests. If `currentTransactionJWS` is nil, throw `AIError.subscriptionRequired`.

- **Rewire `buildStreamRequest`:** Same proxy routing. URL becomes `ProxyConfig.baseURL + "/v1/stream"`. Add `X-Streaming: true` header. Keep `"stream": true` in body.

- **Update `streamRun` return type:** Change from `AsyncThrowingStream<String, Error>` to `AsyncThrowingStream<StreamEvent, Error>`. In the SSE parsing loop, check if a parsed JSON has a `"metadata"` key -- if so, yield `.metadata(...)` instead of `.token(...)`. For `[DONE]`, break as before.

- **Handle proxy error responses:** In `complete()`, after checking HTTP status:
  - On 401: throw `AIError.subscriptionRequired`
  - On 429: parse `Retry-After` header, throw `AIError.rateLimited(retryAfter:)`
  - On other non-200: throw `AIError.httpError` as before
  Same handling in `streamRun` for the initial response status check.

- **Extract metadata from non-streaming responses:** In `complete()`, after receiving response, read `X-Input-Tokens`, `X-Output-Tokens`, `X-Estimated-Cost-USD` from response headers. Store in a new `@MainActor` published property `lastCallMetadata: CallMetadata?` on AIService (struct with inputTokens, outputTokens, estimatedCostUSD).

IMPORTANT: Do NOT change `improve()`, `suggestVariables()`, `autoTag()`, `qualityScore()`, or `clusterPrompts()` signatures -- they still return their existing types. Only the internal `buildRequest` routing changes. The `streamRun` signature change (String -> StreamEvent) is the only public API change.
