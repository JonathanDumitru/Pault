<task type="auto">
  <name>Task 1: Audit animations for Reduce Motion compliance and add polish</name>
  <files>Pault/**/*.swift, PaultUITests/ReduceMotionUITests.swift</files>
  <action>
    1. Reduce Motion audit: Search the entire codebase for animation call sites:
       - `grep -rn "withAnimation\|\.animation(" Pault/` to find all animation usage
       - For each call site, verify it checks `@Environment(\.accessibilityReduceMotion)`:
         - `withAnimation` calls should use a conditional helper or inline guard
         - `.animation()` modifiers should pass `nil` when `reduceMotion == true`
       - If a view uses animation but does NOT check Reduce Motion, add the guard.
       - Use `@Environment(\.accessibilityReduceMotion) var reduceMotion` in each animated view.
       - Note: macOS uses `@Environment(\.accessibilityReduceMotion)` -- NOT `NSWorkspace.shared.accessibilityDisplayShouldReduceMotion` in SwiftUI code.

    2. Spring parameter calibration (per research Pattern 3):
       - Review all `.spring()` parameters against macOS HIG guidelines:
         - Button press: `.spring(response: 0.18, dampingFraction: 0.7)`
         - Panel slide-in: `.spring(response: 0.35, dampingFraction: 0.85)`
         - Copy toast: `.spring(response: 0.3, dampingFraction: 0.65)`
         - List row hover: `.easeOut(duration: 0.12)`
         - Block expand/collapse: `.spring(response: 0.4, dampingFraction: 0.8)`
       - Replace any `withAnimation(.default)` with explicit animation type
       - Ensure dampingFraction >= 0.65 on all macOS animations (no bouncy animations)

    3. Empty state audit: Check every list/collection view for empty state handling:
       - SidebarView: empty collection list
       - Prompt list: no prompts matching search/filter
       - Block editor canvas: no blocks added
       - Version history: no versions yet
       - Analytics dashboard: no usage data
       - Run history: no prompt runs
       - Smart collections: no collections created
       - Import preview: no files to import
       For each missing empty state, add a centered VStack with SF Symbol icon + descriptive text + action hint (e.g., "No prompts yet. Click + to create one.")

    4. Error state audit: Check all network/data operations for error handling:
       - AI Assist panel: API failure, proxy unreachable, rate limited
       - Run tab: execution failure, streaming interrupted
       - Import: file read failure, parse error
       - Export: write permission denied
       For each error path, verify there is user-visible messaging with a recovery action (retry button, settings link, or clear explanation).

    5. Create Reduce Motion UI test -- `PaultUITests/ReduceMotionUITests.swift`:
       ```swift
       import XCTest

       final class ReduceMotionUITests: XCTestCase {
           @MainActor
           func testAppLaunchesWithReduceMotionEnabled() throws {
               let app = XCUIApplication()
               app.launchArguments = ["-UIAccessibilityIsReduceMotionEnabled", "1"]
               app.launch()
               _ = app.windows.firstMatch.waitForExistence(timeout: 10)
               XCTAssertTrue(app.windows.firstMatch.exists)
           }
       }
       ```

    6. Run the Reduce Motion test:
       `xcodebuild test -scheme Pault -destination 'platform=macOS' -only-testing PaultUITests/ReduceMotionUITests 2>&1 | xcpretty`

    7. Run full test suite to verify no regressions from animation/UI changes:
       `xcodebuild test -scheme Pault -destination 'platform=macOS' 2>&1 | tail -10`
  </action>
